NEXUS UI — DIGITAL STARTER KIT CAHIER DES CHARGES COMPLET ET VISION DU
PROJET

Version : 1.0 Objectif : créer une base de projet numérique moderne,
professionnelle, réutilisable et évolutive pour les futurs projets web
et digitaux.

====================================================================== 1.
VISION GÉNÉRALE
======================================================================

Le projet doit être bien plus qu’un simple template ou qu’une landing
page.

Il doit constituer :

-   Un projet réel et fonctionnel.
-   Un laboratoire de design.
-   Une bibliothèque de composants réutilisables.
-   Une bibliothèque d’animations.
-   Une base technique pour les futurs projets.
-   Une référence visuelle professionnelle.
-   Un système de travail structuré pour l’intelligence artificielle.
-   Une base pouvant être montrée dans un portfolio ou à des clients.

Objectif principal :

Construire une infrastructure de création numérique capable de produire
des applications modernes, cohérentes, animées, maintenables,
responsives et professionnelles.

Le projet doit être conçu pour pouvoir être réutilisé dans : - Des sites
vitrines. - Des SaaS. - Des dashboards. - Des portfolios. - Des
plateformes digitales. - Des applications métier. - Des interfaces
administratives. - Des expériences interactives.

L’IA ne doit pas seulement générer du code. Elle doit agir comme : -
Directeur artistique. - UX designer. - UI designer. - Architecte
logiciel. - Développeur front-end. - Expert en motion design. - Expert
responsive. - Expert accessibilité. - Contrôleur qualité. - Responsable
de la documentation.

======================================================================
2. PRINCIPES DIRECTEURS
======================================================================

Le projet doit respecter les principes suivants :

1.  La qualité visuelle ne doit pas être sacrifiée à la vitesse.
2.  Les composants doivent être réutilisables.
3.  Les animations doivent servir l’expérience utilisateur.
4.  Le design doit être cohérent sur toutes les pages.
5.  Le responsive doit être réel et testé.
6.  Le code doit être propre, maintenable et documenté.
7.  L’IA doit vérifier son travail avant de déclarer le projet terminé.
8.  Les bibliothèques doivent être utilisées lorsqu’elles apportent une
    réelle valeur.
9.  Le projet doit être performant et accessible.
10. L’inspiration visuelle ne doit pas devenir une copie d’un site
    existant.
11. Les interfaces doivent être utilisables sur desktop, tablette et
    mobile.
12. Le système doit pouvoir évoluer avec de nouveaux composants et de
    nouvelles fonctionnalités.

======================================================================
4. STACK TECHNIQUE RECOMMANDÉE
======================================================================

Stack principale :

-   Framework : Next.js.
-   Interface : React.
-   Langage : TypeScript.
-   Styles : Tailwind CSS.
-   Composants : shadcn/ui.
-   Animations complexes : GSAP.
-   Animations liées au scroll : GSAP ScrollTrigger.
-   Défilement fluide : Lenis, si pertinent.
-   Animations simples : Motion.
-   Icônes : Lucide React.
-   3D optionnelle : Three.js et React Three Fiber.
-   Backend optionnel : Supabase.
-   Déploiement : Vercel.

Règles d’utilisation :

-   Motion doit être utilisé pour les transitions et interactions
    simples.
-   GSAP doit être utilisé pour les timelines et animations complexes.
-   ScrollTrigger doit être utilisé pour les animations pilotées par le
    scroll.
-   Lenis ne doit être utilisé que si le défilement fluide apporte une
    réelle valeur.
-   Three.js ne doit être ajouté que si une expérience 3D est justifiée.
-   Éviter d’installer des bibliothèques inutiles.
-   Éviter les conflits entre plusieurs systèmes d’animation.
-   Préserver les performances et l’accessibilité.

7. ARCHITECTURE DES ANIMATIONS ET DU MOUVEMENT
======================================================================

Les animations doivent être organisées dans une architecture claire.

7.1. Défilement vertical

Le comportement principal doit être : - Fluide. - Naturel. -
Responsive. - Compatible clavier. - Compatible tactile. - Compatible
lecteur d’écran. - Compatible reduced motion.

7.2. Défilement horizontal

Prévoir des démonstrations de : - Galerie de projets. - Présentation de
fonctionnalités. - Timeline. - Collection de composants. - Parcours
visuel. - Comparaison de solutions.

Utiliser : - Défilement natif pour les carrousels simples. - GSAP et
ScrollTrigger pour les séquences complexes.

7.3. Sections épinglées

Prévoir des sections où : - Le titre reste visible. - Les cartes
défilent horizontalement. - Une illustration évolue. - Une timeline se
construit. - Le contenu change progressivement.

7.4. Parallaxe

Utiliser la parallaxe pour : - Arrière-plans. - Illustrations. -
Décors. - Images. - Éléments graphiques.

La parallaxe doit rester légère et ne pas nuire à la lisibilité.

7.5. Interactions au curseur

Prévoir éventuellement : - Hover. - Magnetic buttons. - Tilt léger. -
Cursor follow. - Effets de profondeur. - Déplacement subtil. - Highlight
au survol.

7.6. Animations de texte

Prévoir : - Reveal. - Split text. - Apparition par mots. - Apparition
par lignes. - Masques. - Transitions typographiques. - Animations de
compteurs.

7.7. Transitions de pages

Prévoir : - Fade. - Slide. - Scale. - Transition de contenu. -
Transition de layout.

7.8. Règles motion

-   L’animation doit renforcer la compréhension.
-   Éviter les animations partout.
-   Éviter les mouvements trop rapides.
-   Éviter les mouvements qui provoquent des nausées.
-   Ne pas bloquer la navigation.
-   Respecter prefers-reduced-motion.
-   Éviter les layout shifts.
-   Préserver les performances mobiles.

11. RESPONSIVE DESIGN
======================================================================

Le responsive doit être traité comme une fonctionnalité essentielle.

Tailles à vérifier :

Desktop : - 1440 px. - 1280 px. - 1024 px.

Tablette : - 834 px. - 768 px.

Mobile : - 430 px. - 390 px. - 375 px. - 320 px.

Vérifications obligatoires : - Aucun texte ne déborde. - Aucun bouton ne
sort de son conteneur. - Aucun titre ne casse la mise en page. - Aucun
mot ne dépasse de son bloc. - Les espacements restent cohérents. - Les
grilles s’adaptent. - Les images conservent leur ratio. - Les menus
mobiles fonctionnent. - Les sections horizontales restent utilisables au
tactile. - Les animations ne bloquent pas la navigation. - Les tableaux
larges disposent d’un comportement adapté. - Les formulaires restent
utilisables. - Les textes restent lisibles. - Les zones tactiles sont
suffisamment grandes.

L’IA ne doit pas déclarer le projet terminé uniquement parce que le code

16. VISION À LONG TERME
======================================================================

Le Starter Kit doit évoluer progressivement.

Évolutions possibles : - Ajout de nouveaux composants. - Ajout de
nouvelles animations. - Ajout de nouveaux thèmes. - Ajout de nouvelles
grilles. - Ajout de nouvelles variantes de pages. - Ajout de composants
de dashboard. - Ajout de composants e-commerce. - Ajout de composants
SaaS. - Ajout de composants mobiles. - Ajout de modèles de
formulaires. - Ajout de modèles de navigation. - Ajout de modèles de
pages marketing. - Ajout de modèles de pages d’administration. - Ajout
de tests automatisés. - Ajout de tests visuels. - Ajout de documentation
interactive.

Le projet doit devenir une base personnelle de production numérique.

======================================================================
17. RECOMMANDATION PROFESSIONNELLE FINALE
======================================================================

Il est recommandé de construire le projet en trois niveaux.

Niveau 1 — Foundation - Next.js. - TypeScript. - Tailwind. -
shadcn/ui. - Design tokens. - Layouts. - Composants essentiels. -
Responsive. - Accessibilité. - Documentation de base.

Niveau 2 — Premium UI - Direction artistique. - Illustrations. -
Patterns. - Bento grids. - Sections éditoriales. - Cartes premium. -
Typographie. - Transitions. - Micro-interactions. - Modes clair et
sombre.

Niveau 3 — Motion & Experience - GSAP. - ScrollTrigger. - Lenis si
nécessaire. - Scroll horizontal. - Parallaxe. - Text reveal. - Page
transitions. - Animations complexes. - 3D si nécessaire.

Il ne faut pas commencer par les effets les plus complexes. Une
animation impressionnante sur une mauvaise structure reste une mauvaise
expérience.

La priorité doit être :

1.  Architecture.
2.  Design system.
3.  Composants.
4.  Pages.
5.  Responsive.
6.  Accessibilité.
7.  Animations.
8.  Tests.
9.  Correction.
10. Documentation.

======================================================================
CONCLUSION
======================================================================

NEXUS UI doit être conçu comme un premier produit de fondation.

Ce projet doit permettre de démarrer rapidement de futurs projets tout
en conservant : - Une qualité visuelle professionnelle. - Une
architecture propre. - Une cohérence de design. - Des composants
réutilisables. - Des animations maîtrisées. - Une expérience
responsive. - Une documentation claire. - Un processus de contrôle
qualité strict.

La formulation centrale du projet est :

« Construis une infrastructure de création numérique capable de produire
des applications modernes, cohérentes, animées, maintenables,
responsives et professionnelles. Tu dois rechercher, recommander,
concevoir, développer, tester, corriger et documenter le projet. Tu ne
dois pas déclarer le travail terminé tant que chaque page, chaque
composant, chaque animation et chaque format d’écran n’a pas été
vérifié. »
